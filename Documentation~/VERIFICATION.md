# ToonPBR for URP — 動作検証チェックリスト

**静的検査で分かることは出し切ってある**（`python check.py --self-test`）。
ここに書くのは**絵を見ないと分からないこと**だけ。

上から順に、**前の項目が通ってから次へ**進むこと。

## 数式として確かめ終わっていること（目で見る必要が無い）

**「静的検査が通った」より強い**。式そのものを数値で検算したか、
公開されている形と一文字ずつ突き合わせたもの。**ここは絵を見ても分からない**
（どれも「間違っていても、それらしい絵にはなる」種類）。

| 何を | どう確かめたか | 結果 |
| :--- | :--- | :--- |
| GGX の分布と可視項 | Heitz の高さ相関の厳密形と突き合わせ | 一致 |
| 異方性 GGX（髪） | Filament の `D_GGX_Anisotropic` / `V_SmithGGXCorrelated_Anisotropic` と突き合わせ | 一致 |
| Charlie 分布（布） | Estevez & Kulla の形と突き合わせ | 一致 |
| EnvBRDF の近似 | Karis（UE4 `EnvBRDFApprox`）と突き合わせ | 一致 |
| sheen の指向性アルベド | 半球積分を数値で解いて多項式と比較（格子を倍にして収束確認） | 最大誤差 0.031 / RMS 0.005 |
| 多重散乱の補償 | Ess ≤ 1・粗さに対して単調・誘電体の正面が f0 | すべて成立（T-261）|
| 補償が Filament と違う理由 | B 項で割った場合の誘電体の倍率を実測 | **発散する**。Ess で割るのが正しい |
| 拡散の wrap | エネルギー保存形（`(NdotL+w)/(1+w)²`）と突き合わせ | 一致。上限 1/(1+w) は仕様 |
| **曲率推定** | 球・円柱・平面で真値と比較（足の形も振る） | **球・円柱とも厳密**（T-273 で修正済み）|
| 前髪透過のステンシル | 46 マテリアルを横断で突き合わせ（書く側・抜く側・Queue 順） | 成立している |
| 画面空間輪郭の経路 | DepthNormals の A → 輪郭シェーダー → Feature の入力要求 | 繋がっている（未使用）|
| 髪の影の深度 | 焼く側と受ける側が同じ行列・比較方向・範囲外・OFF 経路 | 一貫している |
| ディゾルブの網羅 | 形を持つ 7 パスすべてが同じ式で切るか | 揃っている（T-264 で修正済み）|
| Renderer Feature の名前 | `ShaderTagId` / `FindPass` の引数とシェーダーの宣言 | 一致（W111 が常時見張る）|

**逆に、ここに無いものは確かめていない。** 特に:
拡散の伝達関数が**絵として**妥当か、影色の HSV が**好みに合うか**、
リムの太さが**引きの画で見えるか**は、下の項目で目を使うしかない。

## 前提 — **これが揃っていないと、以下は何も検証できない**

**先に `python check.py` を通すこと。** 赤が残ったまま下の項目を見ると、
「シェーダーが悪い」という誤った結論に着くことがある。実際に起きた形:

| 診断が出していたもの | 見ていた項目 | 何が起きたか |
|---|---|---|
| サーフェスタイプが Default | 髪の異方性ハイライト | **出るはずがない。** 髪の 2 バンドは `_SURFACETYPE_HAIR` の裏にあり、Default では 1 命令も走らない。「値が悪い」と読んでいた |
| `ToonOutlineFeature` が未導入 | 輪郭 | **描かれない。** 輪郭は独自 LightMode にあり、URP は既定で描かない |
| 深度テクスチャを作らない品質レベル | リムの太さ | シルエット検出が未定義の深度を読む。**全面に出るか一切出ないか**に倒れる |

**部位別の中身はすべて `_SurfaceType` の裏にある。**
髪の異方性 2 バンド・天使の輪・毛束ノイズ・毛流れ、顔の SDF、肌の SSS、
布の Charlie sheen ── Default ではどれも動かない。
**例外も警告も出ず、絵は普通に出る**ので、見ているだけでは気付けない。

- [ ] `python check.py` が緑（または残りが**意図した**判断待ちだけ）
- [ ] キャラを選んで `Tools > Idol > サーフェスタイプを名前から設定`
      ── 「変えるものはありません」と出れば揃っている

## 0. コンパイル（**通っている。ただし全バリアントではない**）

分割で 15 ファイルになった件は、**Editor が実際に取り込んでエラーを出していない。**
機械で確かめられる:

```bash
cd Assets/ToonPBR && python editor_log_check.py .
```

Editor 自身のログを読む。`実コンパイル: エラー 0 件` と出れば通っている。
**`未検証` と出たらそれは合格ではない** ── ログがソースより古い、つまり
まだコンパイルしていないだけ。Unity にフォーカスを戻すとリフレッシュが走る。

**ここで確かめられるのは Unity が実際に必要とした分だけ。** ログには失敗しか
残らないので、何組コンパイルされたかは分からない。**キーワードの組み合わせで
だけ壊れる不具合はこの経路では出ない**（T-085 で髪のパスが全滅したときも
「0 errors」と報告された）。56 組を通すには Editor を閉じて:

```bash
cd Assets/ToonPBR && python check.py --unity "<Unity.exe>"
```

**Editor が開いている間は batchmode がそもそも起動できない**（グローバルキャッシュの
ロックで Unity が落ちる）。別プロジェクトを立てても回避できない。

エラーが出るなら、**行番号のファイル名**を見ること ── `Passes/` や `Shading/` を
指していれば分割の問題、`Idol.shader` なら pragma まわり。

## 2. アンチエイリアス（未対応・効果が大きい）

**現状 MSAA もカメラ AA も無効**（`param_check` が毎回警告している）。

- [ ] `ToonPBRTest.unity` のカメラの Anti-aliasing を **SMAA** にする
- [ ] 髪の先・睫毛を見ながらカメラをゆっくり動かす → **ちらつきが減るか**

減るなら、残りのちらつき調査の対象が大きく減る。

### TAA を試すなら

前提はすべて揃えてある（MotionVectors パスを追加済み・Skinned Motion Vectors 有効・
透明マテリアル 0 件）。

- [ ] Anti-aliasing を **TAA** に
- [ ] **キャラをアニメーションさせながら**カメラを振る
- [ ] 髪の先や指の輪郭が**尾を引かない**こと

尾を引くなら SkinnedMeshRenderer の Skinned Motion Vectors を確認。

## 6. 前髪透過（新規・T-223）

**既定 OFF なので、何もしなければ絵は変わらない。** 試すには 3 つ揃える。
インスペクタの Stencil セクションにボタンがある。

- [ ] 眉のマテリアルで「**眉 (bit 2 を書く)**」を押す
- [ ] 目のマテリアルで「**目 (bit 4 を書く)**」を押す
- [ ] 髪のマテリアルで「**髪 (透過を有効化)**」を押す
- [ ] 前髪の下に眉・睫毛が透けて見えること
- [ ] `See-Through Alpha` を 0 ↔ 1 で振って濃さが変わること

**上の「瞳 (前髪を抜く)」とは別方式なので併用しないこと。** あちらは瞳が
不透明で手前に出る。ビットは分けてあるので誤爆はしないが、絵としては両立しない。

うまくいかないときの見どころ:

| 症状 | 原因 |
|---|---|
| 何も透けない | 髪の Render Queue が眉・目より**前**。髪を 2010、眉と目を 2000 に |
| 全部透ける／別の場所が透ける | Render Mode で Queue が動いた。**部位の Queue を優先すること** |
| 斜めから見ると睫毛が濃い | 透過ではなく**眉のアウトライン**が髪を突き抜けている。Outline Width を 0 か Z Offset を上げる（ZTest / ZWrite で直そうとしないこと・移植元で検証済み） |
| 穴の縁で色が段になる | ライティングのキーワードがずれている。`PassSets` の組を確認 |

### アルベドの HSV 補正（新規・T-225）

**既定は無変化。** Base セクションにある。

- [ ] `Albedo Hue Shift` を振って色相が回ること
- [ ] `Albedo Value` を **1 以上**に上げても白飛びしないこと
      （反射率として 1 で頭打ちにしてある。**移植元はここが抑えられていない**ので、
      1 以上を入れていたマテリアルは移行後に暗く見える）

### シアー生地（新規・T-229）

**既定 OFF。** Surface Type が Skin か Cloth のとき「Sheer Fabric」に出る。

- [ ] `Stocking Intensity` を上げると布が乗ること
- [ ] **正面と縁で濃さが違う**こと（正面は肌が透け、シルエットへ寄るほど密）
- [ ] `Front Opacity` を 0 にすると正面が完全に透けること
- [ ] **影の中でも布の色が残る**こと（拡散色を作る前に掛けているため）

**光沢は Cloth - Sheen で出すこと。** 移植元の加算「すそ光沢」は
入れていない ── ToonPBR の Charlie sheen と二重になるため。
移行の下見にも「落ちる」として出る。

## 8. 鏡面が明るくなったことの確認（T-246）

**可視項を厳密形にしたので、体の鏡面が明るくなっています**（最大 27% / RMS 13%）。
髪は元から厳密形だったので変わりません。

- [ ] 金属パーツ・真珠ビーズのハイライトが飛んでいないか
- [ ] **髪と体で同じ材質のものが同じ明るさに見えるか**（食い違いが解消しているはず）
- [ ] 飛んでいるなら `Specular Intensity` を 0.2 → 0.16 ほどへ詰める

**代償は +4 命令**でした（最も重い組では変化なし）。性能面で戻す理由はありません。

## 9. 曲率の修正（T-273・**絵が変わる**）

腕・脚・指のような**円柱に近い形**で、明暗境界の柔らかさが変わる。
球に近い形（頬・鼻・指先）は元から厳密だったので変化しないはず。

1. **腕を見下ろす角度**にカメラを置き、Directional Light を横から当てる。
   上腕・前腕の境界が**今までより柔らかくなる**はず ── これが直った本体
2. **その状態でカメラを腕の周りに回す。** 境界の硬さが**動かなくなる**こと。
   以前は画素の伸びる向きが変わるたびに硬さが揺れた
3. **頬・鼻・指は変化しないこと。** ここが変わったなら別の問題
4. 効きすぎるなら `_CurvatureSoftness`（既定 0.8）を下げる ──
   曲率が正しく出るぶん、同じ設定でも効果が強くなる

## 10. 細い影のちらつき（T-287・**設定の問題であって欠陥ではない**）

前髪が顔に落とす細い影が、カメラや頭の動きでちらつくことがある。
**影の境界 AA は正しく組まれている**（`fwidth` をフラグメントで取り、
HQ とコンタクトを畳んだ後に効かせる）。噛み合わせの問題。

数えると分かる ── 影マップの 1 テクセルに対して毛束が細すぎる。
**寸法は書き写さないこと。** URP アセットの設定で変わる。
`Tools > Idol > プリセットを適用` の「ちらつき対策」が
いまの設定から計算して出す。

増幅の経路は 2 つあり、**片方を塞ぐともう片方が開く:**

1. `_HQShadowOn` OFF + 硬いセル → URP 標準の数タップの揺れがそのまま on/off に
2. `_HQShadowOn` ON + 接地硬化 → **8 タップのブロッカー推定が当たらない**。
   ブロッカーが数テクセルしか無いと推定がばらつき、半径が画素ごとに
   1.0〜8.4 テクセルの間で振れて「まだら」になる

- [ ] 「ちらつき対策 ①」（接地硬化だけを切る）で頭を振り、ざわつきが止まるか
- [ ] 止まらなければ ②（可動域を狭める）③（境界を柔らかく）を足す
- [ ] それでも残るなら専用の髪影へ移す（手順はプリセットの説明にある）

**解像度を上げるだけでは足りない。** 4096 → 8192 にしても毛束は
2.9 テクセルにしかならず、揺れは残った。

## 12. 描画コスト（T-301〜T-304・**絵は変わらない**）

**ここは目で見ても分からない。** 絵が 1 ピクセルも変わらないまま
draw が倍になっていたり、早期 Z を捨てていたりする。
確認はフレームデバッガと、シェーダーのインスペクタで行う。

### 押す順番

**絵が変わらないものを先に**。変わるものを先に入れると、
どちらの影響か切り分けられなくなる。

- [ ] `Tools > Idol > 使っていない重ね描きパスを止める`
      ── `HairSeeThrough` は `SRPDefaultUnlit` にあり **URP が既定で描く**。
      透過を使わない材質まで前方描画で 2 回描かれている
- [ ] `Tools > Idol > サーフェスタイプを名前から設定`（**絵が変わる**）
- [ ] Play 中の顔 Renderer が SRP Batch に残ることを Frame Debugger で確認
      ── `FaceDirectionBinder` は Play=マテリアルインスタンス / Edit=MPB の
      二層方式へ変更済み（`Write To Material` トグルは廃止・操作は不要）

### 見どころ

| 見る場所 | 期待 |
|---|---|
| `Idol.shader` のインスペクタ上部 | **SRP Batcher compatible** と出ている |
| フレームデバッガの `SRP Batch` | キャラのマテリアルがまとまっている。分かれていたら「Batch cause」を読む |
| 同・前方描画の draw 数 | 重ね描きを止めた前後で**約半分**になる |

**毎フレーム実際に描かれるのは 4 パス**（ForwardLit / SRPDefaultUnlit /
DepthOnly / ShadowCaster）。Outline と HairShadow は
**Renderer Feature を入れるまで一度も描かれない。**

### 早期 Z

`clip()` を持つ材質は**早期 Z を使えない。** `_BaseMap` にアルファの器が
無ければ `clip()` は 1 画素も落とさないので、払っているだけになる。

- [ ] 診断が「アルファが無いのにクリップしている」と言う材質で
      Alpha Clip を切り、絵が変わらないことを確かめる

## 判断待ち（絵を見て決めるもの）

| | 内容 |
|---|---|
| 接地硬化 | 物理としては意味が無い（真の半影が 1 テクセル未満）。**ただし切ると絵が変わる** ── 下記 |

**接地硬化は「切っても失うものが無い」ではない。** **86 件中 66 件**が
`_ShadowContactHardening = 1` / `_ShadowPenumbraScale = 200` /
`_HQShadowOn = 1` になっており、**演出として現に効いている。**
（診断が 1 キャラ 46 件しか見ていなかった頃の数字を更新した ── T-297）

```hlsl
float penumbra = abs(coord.z - avgBlockerZ) * _ShadowPenumbraScale;  // 200
radius = clamp(penumbra * radius, 1.0, radius * 3.0);                // 1.0〜8.4 テクセル
```

`_HQShadowSoftness = 0.3` なので基準半径は 2.8 テクセル、
接地硬化がそれを**1.0〜8.4 テクセルの間で動かしている**。
切ると全部が 2.8 テクセル固定になる ── 遮蔽物が近い所（顎の下・脇）は
今より柔らかく、遠い所（頭が床に落とす影）は今より硬くなる。

物理としての主張は正しい（真の半影は鼻→頬 0.19mm、腕→胴 1.85mm で、
どれもテクセル寸法を下回る。頭→床の 13.9mm だけが解像できる）。
**だが 200 倍しているのは物理を狙っていないから**で、
「物理的意味が無いから切ってよい」とは繋がらない。

- [ ] 切って比べるなら `_ShadowContactHardening` を 0 にして**顎の下と脇**を見る
- [ ] フェッチ 8 回ぶんの得と、その差が釣り合うかで決める

**決まったもの:** 2影は**実装しない**（階調を増やさない設計を保つ）。
鏡面の可視項は**厳密形にした**（T-246）。曲率は**軸ごとの最大**にした（T-273）。

## 絵を見なくても決められる判断待ち

**絵は変わらない。** コストか作法の話なので、方針だけ決めれば実装できる。
数字は `hlsl_compile.py --branch-cost --materials <dir>` の実測（T-259）。

| | 得られるもの | 代償 |
|---|---|---|
| `_HairShadowOn` ほかを `shader_feature` に | **−333 命令**（基準 1,109 の 30%）。**86 件**全部で OFF なので**出荷物からは丸ごと消える** | 宣言上のバリアント数が倍。ARCHITECTURE.md 設計ルール 2 が「キーワードは許可制」としているので、`ALLOWED_KEYWORDS` への追加という手続きが要る |
| **66 件**の `_MatCapIntensity` を 0 に | **−42 命令**。`_MatCapTex` 未割り当てで**加算が 0** なので絵は 1 画素も変わらない | お手元の `.mat` を 46 個書き換える |
